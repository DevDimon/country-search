# DESIGN

## 1. Отмена устаревших запросов: как устроена и почему именно так

### Проблема

Пользователь печатает `sp`. Запрос уходит в сеть. Пользователь продолжает печатать — теперь в поле `spain`. Если ответ на `sp` придёт **после** ответа на `spain`, наивная реализация отрисует на экране устаревшие данные: `sp` перезапишет `spain`. Это классическая гонка устаревших ответов (stale-response race).

### Решение

Каждое изменение ввода вызывает `CountrySearchController.setQuery()`, который **синхронно** вызывает `cancelActive()`:

1. `cancelActive()` очищает таймаут предыдущего запроса через `dispose()` (чтобы таймаут не сработал уже после отмены).
2. Вызывает `AbortController.abort()` на предыдущем запросе. Это распространяется в `fetch`, промис реджектится с `AbortError`, сеть реально прекращает передачу.

**Ключевой момент:** отмена происходит **на каждом изменении ввода**, а не в момент, когда debounce фактически запускает новый сетевой запрос. Если бы мы отменяли только при старте нового fetch, устаревший ответ мог бы прилететь в течение 350-миллисекундного окна debounce и отрисоваться под уже новым текстом в поле.

### Почему AbortController, а не флаг «актуальный ли это ответ»

Флаг «latest request id» может **предотвратить рендер** устаревших данных, но не может **остановить запрос**:

- Браузер продолжает скачивать ответ.
- Сервер продолжает работу.
- Ответ парсится и аллоцируется в памяти, даже если мы его выбрасываем.

`AbortController` **реально отменяет** сетевую передачу (в DevTools → Network такой запрос помечается как _canceled/aborted_), освобождает ресурсы и даёт детерминированный сигнал для catch-обработчика (`AbortError`). В `runSearch` дополнительно стоит проверка `if (this.active !== request) return` — это **defence in depth** для микроскопического окна, когда промис уже разрешился до вызова `abort()`, но она **не является** основным механизмом.

### AbortError vs TimeoutError vs реальные ошибки

`createTimedSignal()` в `src/utils/signals.ts` комбинирует пользовательский `AbortController.signal` с сигналом таймаута через `AbortSignal.any` (с ручным fallback для старых окружений). Таймаут абортит с `new DOMException(..., 'TimeoutError')`.

В catch-блоке `runSearch` различаются:

| Что пришло                      | Что это                                     | Что показываем                  |
| ------------------------------- | ------------------------------------------- | ------------------------------- |
| `name === 'AbortError'`         | Пользователь отменил (новый ввод / очистка) | Ничего                          |
| `name === 'TimeoutError'`       | Настоящий таймаут                           | Ошибку с Retry                  |
| `HttpError` со `status === 404` | Совпадений нет                              | «Ничего не найдено» (не ошибка) |
| `HttpError` с другим статусом   | Ошибка сервера                              | Ошибку с Retry                  |
| Всё остальное                   | Сетевая ошибка / парсинг                    | Ошибку с Retry                  |

### Бонус: кэш + дедупликация и отмена

`createCachedSearch` держит один общий промис на запрос плюс ref-counter. Отмена одного вызывающего:

1. Уменьшает `refCount`.
2. Реджектит только **его** промис через `raceWithSignal`.
3. Общий запрос **продолжается**, пока `refCount > 0`.
4. Когда `refCount === 0`, общий `AbortController` абортится — в Network видно canceled.

Это удовлетворяет обоим требованиям: реальная отмена и дедупликация, при которой один вызывающий не ломает промис другому.

## 2. Обоснование задержки debounce — 350 мс

- **0 мс (без debounce).** Один запрос на каждое нажатие. «spain» = 5 запросов, 4 из которых тут же абортятся. Трафик и мигание loading.
- **Слишком мало (~100–150 мс).** Почти не сокращает число запросов: большинство печатающих делают паузу 150–250 мс между клавишами.
- **Слишком много (~1000 мс).** Пользователь уже закончил печатать, а на экране ничего не происходит секунду — ощущение «тормозит».

350 мс — золотая середина, используемая во многих search-UI:

- Собирает нормальный темп печати в один запрос.
- Воспринимаемая задержка остаётся низкой.
- Намеренно длиннее среднего межклавишного интервала, что **реально** задействует путь «abort во время debounce» в обычном использовании.

Задержка вынесена в `DEFAULT_DEBOUNCE_MS` и инжектится через `CountrySearchControllerOptions.debounceMs`, поэтому её можно подстроить не трогая логику.

## 3. Сложность (Big O)

### `mapCountryResponse(raw)`

- **Time:** `O(L + C + B)`, где `L` — число языков, `C` — число валют, `B` — число границ.
- Для одной страны все три — малые константы, ограниченные размером ответа API. На практике функция **`O(1)`** на страну.
- Маппинг `n` стран: **`O(n)`**.
- **Space:** `O(L + C + B)` для новых массивов. **Вход не мутируется** — `borders` копируется, поэтому вызов безопасен для вызывающего.

### `createCachedSearch` (бонус)

- `Map.get/set/delete` — **`O(1)`** в среднем.
- Вытеснение кэша использует порядок вставки `Map` — **`O(1)`** на вытеснение.
- Дедупликация — ещё один **`O(1)`** lookup в `inFlight`.
- `raceWithSignal` на каждый вызов добавляет ровно один abort-listener и один `then` — **`O(1)`** на вызов.
- **Итог на запрос:** `O(1)` в среднем, плюс `O(k)` самого сетевого вызова.

### `debounce`

- **`O(1)`** на вызов (один `clearTimeout` + один `setTimeout`).
- **`O(1)`** памяти.

## 4. Принципы чистого кода и где конкретно они применены

- **Single Responsibility.**
  - `searchCountries` — только HTTP и семантика 404 (`src/api/searchCountries.ts`).
  - `mapCountryResponse` — чистое преобразование данных (`src/api/mapCountryResponse.ts`).
  - `CountrySearchController` — только оркестрация состояния, debounce и отмены (`src/app/CountrySearchController.ts`).
  - `debounce` — только планирование вызова (`src/utils/debounce.ts`).
  - `createCachedSearch` — только кэш и дедупликация (`src/api/cachedSearch.ts`).
  - `mountApp` — только DOM (`src/ui/mountApp.ts`).

- **Dependency Injection / тестируемость.**
  - `CountrySearchController` принимает `search` через конструктор — тесты подставляют фейк, сеть не трогается.
  - `debounceMs` и `timeoutMs` тоже инжектятся (`CountrySearchControllerOptions`).

- **Чистые функции.**
  - `mapCountryResponse`, `isAbortError`, `isTimeoutError`, `loadHistory` — без побочных эффектов, легко юнит-тестируются.

- **Типизированные ошибки вместо «магических строк».**
  - `HttpError extends Error` с полем `status` (`src/api/HttpError.ts`).
  - `isAbortError` / `isTimeoutError` — маленькие type guards (`src/utils/errors.ts`) вместо разбросанных `error.name === ...`.

- **Именованные константы и ранние выходы.**
  - `BASE_URL`, `DEFAULT_DEBOUNCE_MS`, `DEFAULT_TIMEOUT_MS`, `LIMIT`, `UNKNOWN`, `DEFAULT_MAX_ENTRIES` объявлены один раз.
  - В `runSearch` каждая ветка ошибки — ранний `return`, вложенности нет.

- **Изоляция побочных эффектов.**
  - Вся работа с DOM — только в `src/ui/mountApp.ts`.
  - Вся работа с `localStorage` — только в `src/ui/searchHistory.ts`, обёрнута в `try/catch`.
  - Модули `src/api`, `src/app`, `src/utils` не зависят от DOM и тестируются в Node.

- **Без `innerHTML` / `insertAdjacentHTML`.**
  - Динамический контент — `document.createElement`, `textContent`, `replaceChildren`, `DocumentFragment`.

- **Маленькие функции.**
  - `renderStatus`, `renderResults`, `renderDetails`, `renderHistory`, `metaRow` — каждая делает одно.
  - `toCountryList` изолирует проверку формы payload (array / single object).
